Your agent says all tests pass. Prove it.

MergeGuard reads a coding agent's step-by-step log, finds the exact step where it cut a corner, and sends it back until the fix is real.

    How it works

    1. Evidence. Gather the diff, run the tests for real, and read the agent's step-by-step log.
    2. Hard rules. Plain checks, no AI: did the tests pass, and were any tests deleted, skipped, or edited?
    3. Audit the log. Muse Spark points to the exact step where something went wrong.
    4. Send it back. Hand the agent the evidence and a fix ticket. Check again, up to 3 tries.
    5. Human approval. Risky changes wait for a person to approve them.

    Run it

    1. Install

    git clone https://github.com/PamAntonio/mergeguard
cd mergeguard/verifier
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

    2. Add your Meta Model API key to .env

    cp .env.example .env
# then edit .env and set:
META_API_KEY=your-key-here
META_BASE_URL=
AUDITOR_MODEL=muse-spark-1.3

    3. Run the commands

    # numbered steps from a session log
python -m verifier steps --log <path> [--task <task>] [--json]

# evidence + hard rules only, no AI
python -m verifier rules --repo ../demo-shop --branch task-b --base bug-base --claims ../demo-shop/.claims/task-b.md --log <path>

# full check
python -m verifier verify --repo ../demo-shop --branch task-b --base bug-base --claims ../demo-shop/.claims/task-b.md --log <path>

# send it back (fix loop, up to 3 attempts)
python -m verifier fix --repo ../demo-shop --branch task-b --base bug-base --claims ../demo-shop/.claims/task-b.md --log <path>

# saved report + replay, no API calls
python -m verifier show task-b
